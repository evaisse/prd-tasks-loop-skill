PRD Tasks Loop

PRDs that leave operational evidence.

The runner executes one runnable US-xxx story at a time, rejects incomplete agent runs, and records enough state to resume or debug the loop.

  • Auto-discovers canonical PRDs under docs/prd/
  • Renders one focused prompt for the active story
  • Requires PRD checkbox progress and Git commit proof

Happy path terminal output

          

            A successful PRD prints the PRD index, starts each runnable story, marks each
            story as passed, then reports completion. Runtime logs are cleaned after all
            stories complete.

Runtime state beside the PRD

          

            While a PRD is open, the loop writes visible files next to the Markdown PRD.
            Agents are instructed to read them and never edit them manually.
          

          
    
            
  • *.json.log stores status, active story, retry count, selected agent, and attempt excerpts.
    • 
            
  • *.progress.log records timestamped events such as validation, attempts, backoff, and completion.
    • 
            
  • Both files are removed automatically after the PRD reaches Completed:.
    • 
          

        


        

          
Validation and discovery

          

            With no positional PRDs, only canonical filenames are discovered. Explicit files
            still get full validation, including required sections and story fields.

Story verification

          

            A zero exit code is not enough. The runner verifies that the current story
            advanced its acceptance checkboxes and, in a clean Git repository, created a
            Conventional Commit containing both the story ID and PRD ID.
          

          
    
            
  • exit 65: the PRD file or current story checkboxes did not advance.
    • 
            
  • exit 66: no new story commit was created from a clean worktree.
    • 
            
  • exit 67: the story commit subject is missing the required format or references.
    • 
          

        


        

          
Retries and blocked work

          

            Failed attempts are written into state and progress logs. The loop retries with
            backoff, then stops the current PRD when retries are exhausted or dependencies
            leave no runnable story.
